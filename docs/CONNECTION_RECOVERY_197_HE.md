# שחזור חיבור — מצב לפני סבב הנזק המאושר

8 בנובמבר 2026. לאחר עצירת השליטה ב־Escape המשתמש הפעיל שוב את המטרה. הסבב שאושר196 עדיין לא נשלח: הרשומה `.local/core196-authorization.json` במצב `approved_preparing_not_run` וקובץ ההרצה אינו קיים.

קריאת התהליכים מצאה Fortnite46016 ו־UEFN42160. צילום ממוקד של UEFN מראה ProCoachLab ו־Session Inspector במצב Not connected, וכל שלבי ההכנה Not started. אין מאזין בפורט8000. לוג ההפעלה כולל `MCP auto-start is externally managed; waiting for AutoStartServer()`. לכן יש להפעיל את החיבור לפני שאפשר לקרוא את המתקן השמור או לשלוח את הסבב. צילום רקע שגוי של הדפדפן לא שימש לאבחון ולא נשמר.

הוגשה בקשה אחת למשתמש ללחוץ Start Server ב־Edit → Editor Preferences → Agentic Workflows → Model Context Protocol, בפורט8000. זה הנתיב בתיעוד [UEFN MCP של Epic](https://dev.epicgames.com/documentation/fortnite/uefn-mcp), שנקרא מחדש היום. אין צורך באישור משחק נוסף. לא נשלחו קלט מקלדת או עכבר197; בוצע מיקוד חלון לצורך קריאה, והחיבור לשליטה אופס מיד לאחריה.

הוכן `.local/core197-preflight.py` לקריאת זהויות של שלושת רכיבי196, מקור המתקן, מיקומים, אפשרויות הפיצוץ, הפניות ושערי המוצר לאחר האתחול. הסקריפט טרם הורץ ואינו בדיקת משחק. לאחר חיבור יש לקרוא את תוצאתו, ורק אם המצב תואם להריץ את `.local/core196-run.py` פעם אחת ולאחריה ניקוי באמצעות `.local/core196-cleanup.py`. אין ליצור שוב רכיבים, לחזור על קומפילציה ללא שינוי או להפעיל את176/185 הישנים.

המשך זה השיג אבחון של החיבור והכנת קריאה לאחר האתחול; הוא אינו ראיית נזק, בנייה, עריכה או קבלת מוצר. כל היקף R01–R30/W0–W7 נשאר פתוח בהתאם לראיות הקיימות. התלות הנוכחית היא הפעלת השרת, ולא תהליך משחק שממתין או פרויקט שהושלם.
