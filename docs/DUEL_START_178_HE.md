# הכנת פתיחת1V1סימטרית178

8 בנובמבר2026. הוכנו שתי רמפות קבועות ועמדות פתיחה משותפות לקוד ולפריסה. זו עבודת עורך ומקור, לא קבלת משחק בשני לקוחות או הוכחה לבנייה בידיNPC.

הממצא הקודם בעורך היה `PCL_Duel_Start_Block`: קוביית זהב ברוחב1024ס״מ, מרכזZ40וגובה80ס״מ. המקור שיגר את השחקנים ל־X±512,Z100. לא נמדדה תקלה בגוף שחקן בסידור הזה; ההחלפה נועדה לפתיחה ברורה וסימטרית עם מסלול טיפוס.

| רכיב | תצורה שנקראה בעורך |
|---|---|
| רמפה שמאלית | מיקום(-512,45056,0), yaw−90; גבולותX−512..0,Y44800..45312,Z0..384 |
| רמפה ימנית | מיקום(512,45056,0), yaw90; גבולותX0..512,Y44800..45312,Z0..384 |
| עמדות שחקנים | קוד משותף ל־(-768,45056,100) ו־(768,45056,100), לפני הרמפות |
| הגדרות הרמפות | bPlayerPlaced=False, bCanBeDamaged=False, bIsPlayerBuildable=True, bDoNotBlockBuildings=True, bStructurallySupportOverlappingActors=True |
| משטח | חומר האבן של הערכה בשני חריצי החומר, cast_shadow=False; קריאה ושמירהTrue |
| הבלוק הקודם | הועבר ל־Z−500, הוסתר במשחק וכובתה התנגשות. ההפניה, התצורה והדגלים המקוריים נשמרו; לא נמחק |

נוצר עותק נפרד של נכס הרמפה שבבעלות הפרויקט בשם `PCL_BP_DuelStartingRamp`, בלי לשנות את מקור המועמד או את נכסי הקורס. נעשה שימוש במאפייני העורך הציבוריים ובקומפילצייתBlueprintהבעלים; לא שונו הרשאות, דגליMetadataאוCDOזר. קריאת המופעים הראתה תחילה bCanBeDamaged=TrueלמרותFalseבברירת המחדל. ההגדרה הוחלה גם במופעים דרך המאפיין הציבורי, ונקראהFalse. לאחר התצורה נדרשה החזרת תנוחות המיקום; הרשומה `final_placement` היא ראיית הפריסה הסופית, ולא הגבולות המוקדמים ברשומה.

`arena-layout.json` גרסה4שומר duel_start_half_separation_cm=768. `generate_arena_layout.py` מייצר `CoachDuelStart`, שמשמש גם את הכניסה לזירה וגם את Stageבספירה. הכניסה סופרת את משתתפי הבקר הפעילים באמצעותParticipantsבמקום מפגשים ישנים במפה. שלושת המקורות נכתבו לעורך, התקמפלו ללא אבחונים ונשמרו. זו קומפילציה, לא הפעלת ספירה או הופעה מחדש בפועל.

פריסות: `uefn/duel-start-layout.json`, `uefn/duel-round-layout.json`. מתכון: `tools/author_duel_start.py`; הפעולה הושלמה ואין להריץ שוב גם לא עם--finish. ראיות: `.local/duel-start178-authoring.json` כוללfinal_placementו־surfaces, ו־`.local/duel-start178-source-authoring.json`. תנאי השמירה הראשוני נכשל ונעצר לפני פרישת הבלוק הקודם; ההמשך השתמש באותם שני מופעים, ללא יצירה כפולה. צילוםEditorלפני שינוי החומר ובסופו נשמרו בנפרד; [התצוגה האחרונה](images/procoachlab-duel-start178.png) אינה צילום לקוח או אישור לגימור/תאורה.

נפתחו [מדריך Epic להמרת נכסים ל־Props](https://dev.epicgames.com/documentation/en-us/fortnite/converting-assets-into-props-in-unreal-editor-for-fortnite) ו־[הנחיית Epic לבנייה עלPropsמותאמים](https://forums.unrealengine.com/t/how-can-i-allow-building-on-top-of-a-custom-cube-in-uefn/2448817/11). ההנחיה תומכת בבחירת הגדרות התמיכה למשטח קבוע; אינה הוכחה מקומית לחיבור מבנים, לעריכה, לבעלות או למשבצת native.

בקבלת הסיום יש לבדוק בנייה רגילה משתי הרמפות בשני הצוותים, עמידות באיפוס ובנזק, אפשרויות עריכה סימטריות, גוף שחקן ומצלמה ללא חפיפה, ספירה/שחרור יחד וניקוד. ארבעת שערי הבנייה של היריב לא שונו. מתקן176נותר רדום, ואישור הרצת המנגנון עדיין ממתין.
